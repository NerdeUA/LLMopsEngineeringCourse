Ми виявили збій через статуси в журналі та зміни метрик, а не через HTTP 500 для
користувача. Для запобігання регресії в репозиторії є перевірки fallback,
відновлення й error rate; надалі їх слід регулярно запускати в CI. Під час
першого пробного прогону виявили, що mock не розпізнає англійське `log in`;
формулювання команд runbook уточнено до `login` і перевірено повторно.
