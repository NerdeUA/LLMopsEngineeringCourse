# Домашні завдання

По одному файлу на тиждень. Кожне ДЗ добудовує один шар твого gateway, тож наприкінці
курсу маєш зібраний capstone — окремого «фінального завдання» немає.

| ДЗ | Після уроків | Тема |
|---|---|---|
| [hw1.md](hw1.md) | 1–2 | логування + prompt registry |
| [hw2.md](hw2.md) | 3–4 | routing + cost |
| [hw3.md](hw3.md) | 5–6 | кеш + інструменти |
| [hw4.md](hw4.md) | 7–8 | надійність + безпека |
| [hw5.md](hw5.md) | 9–10 | observability + evals |
| [hw6.md](hw6.md) | 11–12 | CI-гейт + інцидент |

Кожен файл побудований однаково: **Завдання** → **Перевір себе** → Опційно →
Що здаєш → **Критерії перевірки** → навіщо це в реальній системі. Критерії —
короткі; що саме ментор вважає провалом і чому — в [CHECKS.md](CHECKS.md).

## Як здавати

- ДЗ живе у **твоєму** репозиторії (клон стартера — GETTING_STARTED §12, крок 0)
  і після курсу лишається тобі як портфельний проєкт.
- Здача = гілка + Pull Request у власному репо. Репозиторій публічний або приватний
  із ментором у колабораторах. Посилання на PR — у канал потоку.
- В описі PR — що зробив і скрін консолі. Там, де ДЗ просить опис рішень або розділ
  README, — це такі самі артефакти перевірки, як код.
- Кожне наступне ДЗ гілкуй від `main` **після мержа попереднього**, інакше в diff
  буде минулий тиждень і перевірка сповільниться.
- Дедлайн — PR **протягом тижня від видачі ДЗ** (другий урок тижня). Пізніші PR
  перевіряються за SLA наступного тижня. Тижні 4 і 6 важчі за інші — розкладай їх
  на два підходи всередині тижня.
- Перевірка — 2–3 доби. Вердикт — **«зараховано»** або **«на доопрацювання»**
  з максимум трьома головними зауваженнями; решта — інлайн-коментарі в код.
- Критерії перевірки відкриті й не змінюються протягом потоку.

## Як працювати

- Місця в коді підписані `TODO(student, W#)` у `service/Program.cs`.
- Все робиться на mock, без реального ключа.
- Evals ганяються командою з GETTING_STARTED §6. Як runner влаштований усередині,
  розбирається на уроці 10; до того — користуйся ним як чорною скринькою.
- Орієнтир по часу: 2–3 години після guided lab. Виходить суттєво більше — неси
  питання в канал потоку, не закопуйся.
- Застряг? Еталонні рішення є, доступ відкриває ментор **за запитом** — після
  власної спроби.

## Опційне (за бажанням, не оцінюється)

Повний перелік — у файлі ДЗ тижня. Найбільші теми: semantic cache (hw3) ·
circuit breaker з half-open (hw4) · regex-детект prompt injection і HITL TTL (hw4) ·
SLO з бюджетом помилок, таксономія помилок і model-based grader (hw5) ·
canary-план та `/metrics` із зовнішнім дашбордом (hw6).
